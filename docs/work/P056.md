## B. Items (LexaVault uses 1 first; Vero needs 4 for its task 0082)

1. **LV-25.1, `platform-fields`: a batch read of records.** A `default` method on the `ValueStore` SPI that reads a list of records in one query (the default loops over `find`, so other stores keep working); `PostgresValueStore` does one `select … where … in/any(?)` per page, keeping the scope checks. `FieldValues.read(List<RecordRef>)` and `readSensitive(List<RecordRef>)` use it, so a page is **one database query and one key-service call**. Same limit (100), same per-record results and errors as 1.1.0's `readSensitive(list)`. Measure a page of 25: queries before and after, in the report.
2. **LV-23, `platform-identity`: activating a login connection can't lock everyone out.**
   - (1) Before `LoginConnections.activate` switches the issuer, a **test sign-in check** must have passed for that draft (a hook the app calls with a real test sign-in against the new issuer, or a module check of the issuer's discovery and keys plus a recorded test sign-in; choose the safer one that works for an app with one fixed decoder, and document the app's duty). Activation without a passed check is refused with a published code (a new code is additive here; say why it can't break a switch).
   - A **rollback that needs no signed-in session**: the setup command gets `identity rollback-login-connection` (setup login), and the guide says when to use it.
   - (2) **Drafts carry their customer**; every draft call checks it in the module (another customer's draft is refused as not found). Additive schema change if a column is needed, with a migration that fills existing drafts or marks them for re-creation (decide, record).
3. **LV-24.2, `platform-notifications`: several mail servers per tenant, as a setting.** Not by making the channel classes public: a mail server can be chosen per tenant (or per entity) from settings/profile data, one `Notifier` for all. Today's single-server setting keeps working unchanged.
4. **LV-24.5: close an approval decided outside the links.** An API call for the app to mark an approval request decided (by whom, when, the decision) so the one-click links then answer "already decided" with the right decision, and the request's audit shows where it was decided. Vero's case: its own screen decides first (task 0082).
5. **LV-24.4: licence warning days set by the admin**, as the notifications design (7.4) says: a setting within sane bounds, default today's days.
6. **LV-24.10: `LicenceBuild` says whether it is a development build** (a method; the development key's licences answer true).
7. **LV-25.3: `VALUES_CONFLICT` carries the conflicting keys as data** (a method on the exception or its details), not only in the message.
8. **LV-25.4: an all-or-nothing save of a list of definitions** (`FieldDefinitions.change(list)`): every change or none, one transaction.
9. **LV-25.5: `FieldValues` without a `KeyService` when no field is sensitive**: a constructor/builder without it; it refuses clearly (published code) only if a sensitive field is then used.
