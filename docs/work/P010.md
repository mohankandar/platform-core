A. Owner decisions on P009 (apply, and record them plus your P009 decisions 1–17 in a new "Decisions" section of
docs/design/licensing.md):
1. Server clock behind: the app ALWAYS starts. Effective time = the later of the server clock and the last time seen,
   so a rollback can never extend a licence. Report it (state flag + specific message with the exact difference, e.g.
   "server clock is 3 hours behind"); no refusal. Remove LICENCE_CLOCK_ROLLBACK as a start-up refusal. Add a signed
   "last-seen reset" that our side can issue if a wrong future clock ever poisons the last-seen time (format +
   verifier; issuing it can be a CLI option).
2. Early renewal: storing a licence whose start date is in the future keeps the current licence in force until then;
   intake never stops because of an early renewal.
3. One allowance per product and type per slot; storage in whole GB: confirmed.
4. Store the usage chain head (latest sequence and hash) and check it on read, so deleting the newest records is
   detected.

B. Postgres storage (plain JDBC, same pattern as platform-notifications): stored licences (current + waiting),
last-seen time, usage ledger, chain head. SQL under src/main/resources/db/platform/licensing/ (tables prefixed lic_,
own version table), run only by the app's schema step as a separate Flyway run with history table
lic_schema_history. Startup only verifies tables, version and DML rights, with specific messages. No secrets, no
prices, no document data in any table.

C. Licence command (CLI, customer side): store a licence (first install) or renew; verifies before storing; refuses
another customer's licence; idempotent; prints a plain status line (type, kind, entities, expiry or updates-until).

D. Spring wiring in a new module platform-licensing-spring (same layout as platform-notifications-spring; add to build
and BOM): auto-configuration, properties (prefix platform.licensing: trusted public keys by key ID, product code,
clock tolerance), a LicenceService bean apps call (current state, intake allowed, kind/test-environment flag, usage
recorder), startup check (refuse only for: no licence ever stored, forged, tampered, wrong customer, unknown key ID —
each with its code and what to do), health indicator (state, days to expiry, clock behind; no keys, no signatures).

Tests for all of the above, including: restart during grace starts; clock rolled back starts with the alert flag and
cannot extend expiry; poisoned last-seen + valid reset recovers; early renewal waits; deleted newest usage records
detected; startup refusal codes; DML-only user runs everything.
