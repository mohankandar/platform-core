A. Licensing notification events (in platform-licensing-spring; notifications is an OPTIONAL dependency: if the app
has no platform-notifications, licensing still works and simply publishes nothing):
- Offer a helper the app calls when building its EventCatalogue to register the licensing event types, with defaults:
  licence expiring (60/30/7/1 days; business, daily), licence in grace (business, CRITICAL, daily), intake stopped
  after grace (business, CRITICAL), server clock behind (technical, CRITICAL, IT Admin), usage near limit 80% / at
  limit 100% / over limit (business, per entity; daily), app version not covered by the licence's "updates until"
  (technical, IT Admin).
- Licensing is per entity: business licensing events are published per activated entity slot (owner decision).
- Continuous conditions (grace, intake stopped, clock behind, over limit) use conditionFailing/conditionCleared so
  they alert once, repeat, and send Recovered.
- A scheduled check (default hourly) evaluates the state and usage and publishes; restarts never cause duplicate
  alerts.
- Content rule: messages carry only the event, entity, counts/dates and a link; never keys, signatures or prices.

B. Vault Transit signing (our side, issuing command):
- Replace SigningKeyResolver with a signing interface sign(keyId, bytes). Implementations: VaultTransitSigner (JDK
  HttpClient, Vault Transit ed25519 key; the private key never leaves Vault) and the existing env-variable signer kept
  for tests only.
- Key ID = Transit key name + version (e.g. lic-2026:1), so Vault key rotation maps to our key IDs. A command option
  exports the public key(s) from Vault into the trusted-keys format apps ship.
- Vault auth: token from VAULT_TOKEN or a Vault login method; never logged, never in records.
- Write docs/install/licence-signing.md: how to create the Transit key and a Vault policy "licensing-signer" (sign +
  read public key only; no export of private key), and assign it to two named user accounts (owner + backup; names
  only in Vault, never in the repo). Every signing is in Vault's audit log plus our run log.
- Tests with Testcontainers Vault (dev mode): sign and verify end to end, key rotation (old version still verifies), a
  token without the policy is refused with a specific code, Vault unreachable gives a specific code, no token or key
  material in any output.
