## D. Build: value storage in platform-fields (+ spring wiring where needed)

Per docs/design/case-fields.md:

- **Values belong to an app record:** entity, product, record type and record ID (the app's), field key, values (list for multi-value), validated and normalised by `FieldValidator`.
- **Non-sensitive values:** stored as display value + normalised value; search by the field's `SearchMode` (EXACT, PREFIX, PARTIAL). For PARTIAL, use a method the customer's DBA can enable in the schema step (e.g. `pg_trgm`); if it isn't available, partial falls back to prefix with a specific health note, never silently wrong.
- **Sensitive values (rule 6):** never stored readable in any table, log or backup. The record's sensitive values are sealed with `ValueCipher` under one case envelope (B2); each searchable sensitive value also gets a **fingerprint** from `Fingerprinter` (field key as context; capitals and extra spaces ignored) for **exact match only**. Search on a sensitive field with prefix or partial is refused with a specific code. Key rotation: search covers every usable fingerprint key version.
- **Lookup by primary value** (per section C) and the uniqueness rule found there, enforced by the database, safe with concurrent writers.
- **Reading values back:** decrypting sensitive values is an explicit call the app makes only for roles allowed to see them; values never appear in `toString`, logs or exception messages.
- **Postgres storage:** fld_ tables in the same Flyway run (`db/platform/fields`; V1 may still be edited: it was never released). Startup only verifies; DML-only runtime user. Testkit in-memory version with the same rules.
- **Tests:** every type stored and read back; non-sensitive exact/prefix/partial search; sensitive exact search via fingerprint, case and spacing ignored; prefix/partial on sensitive refused; no sensitive value readable in any table column (check the raw rows), log or message; one key-service call per record; key rotation keeps search working; wrong customer refused; primary uniqueness under concurrent writers; setup creates keys and a rerun leaves them; crypto-spring wiring and health.
