### B1. API polling (kind `API_POLL`)

- **Steps:** configured like outbound, with the same templates, sign-in, safety, limits, rules and pinning:
  - a **list** step, with paging by cursor, next link, or page number plus size;
  - a **download** step per item;
  - an optional **acknowledge** step per item.
- **Per item:** a stable **source item ID**, read by a pointer; the values read; the document bytes, streamed, with size limits and SHA-256.
- **One pass:** `PollEngine.pass(stored, cursorState, handler)` runs at most the configured pages per pass and hands each item to the app's `IntakeHandler`.
  - The handler answers `TAKEN`, `ALREADY_TAKEN` (the app's own idempotency) or `REFUSED(code)`.
  - Only after `TAKEN` or `ALREADY_TAKEN` does the module acknowledge, when that step is configured.
- **Result:** the new cursor state (the app stores it), a count per answer, and the usual classified outcome for a failure, with the stop point. A failure partway keeps the cursor at the last fully handled page.
- **Profiles:** `API_POLL` can be described in a profile (format `/1`, additive). Update the schema and its doc.
- **Mock source API** in the testkit:
  - it loads any profile;
  - switches: pages, empty, a broken page, slow, busy, down, a refused download, an acknowledge that fails, duplicates across pages;
  - it records acknowledges.

### B2. Watched folder / share (kind `WATCHED_FOLDER`)

- **Configuration:**
  - the root folder (an absolute local or UNC path);
  - how a drop is found: a **subfolder per drop**, or **files grouped by base name** in the root;
  - the **trigger**, which must come **last**: a file name pattern (for example `*.json`, `*.xml`, `*.lck`, `*.done`, or `<base>.done`);
  - the **stability rule**: sizes and modification times unchanged for N seconds;
  - the **incomplete-drop window**: files present but no trigger after N minutes;
  - the limits: file size, files per drop, and drops per pass.
- **One pass:** `WatchedFolder.pass(stored, handler)`:
  1. find drops that have a trigger and stable files;
  2. claim each one;
  3. scan the files (B3);
  4. hand the drop to the app;
  5. move it by the app's answer.
- **Claim:** atomic rename into `_processing/<drop>-<fence>`, with a fencing token, so two app instances never take the same drop. Afterwards:
  - `_archive/` on `TAKEN` or `ALREADY_TAKEN`;
  - `_problem/` with a small `problem.json` (code, time, never content) on `REFUSED` or a failure;
  - a claim that is stuck (its instance died) is released after a set time.
- **What the app gets** (`Drop`):
  - the drop ID;
  - each file: name, size, SHA-256, a stream;
  - the trigger: name, raw bytes, and its type (JSON, XML, or an empty marker);
  - optionally, **named values extracted by a fixed mapping** the configuration gives, with no scripts:
    - JSON pointers for a JSON trigger;
    - a small path language (element names and attributes, with `[n]` for lists) for an XML trigger.

  **The values carry no meaning in platform-core**: the app decides what "level" or "contract number" means. The app can also ignore the mapping and read the raw trigger.
- **Platform-core reports, without deciding:** files in the drop that the extracted list doesn't name, and names in the list with no file. They are given to the app as two lists.
- **Incomplete drops:** a drop without its trigger after the window is reported once per drop as `INCOMPLETE` (with its age and files), for the app to show IT. Nothing is moved.
- **Codes:** `INT_WATCH_*`:
  - root not found, no permission, share unreachable;
  - a trigger that can't be read (malformed JSON or XML, too large);
  - claim lost (fencing);
  - move failed;
  - a file changed after the claim (checksum).
- **Safety:** the parsers are hardened. XML has no DTDs, no external entities and no XInclude; both XML and JSON have size and depth limits. Never follow links out of the root, whether symlinks or junctions.
- **Mock folder:** extend `MockFolder` with drops that arrive slowly, a trigger before its files, files without a trigger, unreadable triggers, two pass runners racing, and a share that disappears in the middle of a pass.

### B3. Virus-scan hook (requirement 11, optional)

- **Interface** `FileScanner`: `CLEAN`, `INFECTED(name)` or `SCAN_FAILED(code)`, with adapters for **ICAP** (RESPMOD) and **clamd** (`INSTREAM`), over the outbound safety rules (an internal address is allowed on premises). It is off when no scanner is configured.
- **When on:**
  - every incoming file, from polling or a watched folder, is scanned **before the app sees it**;
  - **INFECTED** → quarantined, never handed over: for a folder, the drop goes to `_quarantine/`; for polling, the item is not acknowledged and is reported. An event goes to the app (`ScanEvents`) for its IT alert;
  - **SCAN_FAILED** → held and retried at the next pass, never let through.
- **Health:** a scanner check, as for a destination.
- **Test:** the testkit gets `MockScanner` speaking ICAP and clamd, with switches for clean, infected (EICAR), slow, down and a garbled answer.
