## B. Check each item against `v0.8.0`; fix only what fails

1. **Auto-configuration order:**
   - no `-spring` module orders itself after, or conditions on, a Boot 3 class name that Boot 4 moved, for example `org.springframework.boot.autoconfigure.jdbc.DataSourceAutoConfiguration`, which now lives in Boot 4's own JDBC module;
   - Boot ignores an ordering that names a missing class, silently. Search every `@AutoConfiguration(after/before = …)`, `afterName` / `beforeName`, `@AutoConfigureAfter`, `@ConditionalOnBean`, `@ConditionalOnClass` and `AutoConfiguration.imports`;
   - **Test:** a plain Spring Boot 4.2 app context (JDBC, Actuator and Security starters only) starts with each `-spring` module, and the module's beans are present.
2. **Nimbus JOSE:** no platform pin overrides the version Spring Security 7 declares. `mvn dependency:tree` in an app-like test project shows exactly one Nimbus version, Security's.
3. **One BOM version** brings every module on Boot 4.2.x / Framework 7.1 / Security 7.x / Java 21. Nothing in the BOM still pulls a Boot 3 artifact.
4. **Names apps already use stay public and unchanged,** or are listed in the release notes with their replacement:
   - `IssuerFetch`, `OidcTestSignIn`, `DevelopmentLicence`, `LicenceSigningKey`, `PlatformGroupAuthorization`, `EntityMembershipResolver`;
   - the identity and licensing JDBC stores, `IdentitySchema`, `LicensingSchema`;
   - `SetupCommand`, `MockIssuer`, `ProfileValidator`, `ProfileContract`;
   - the `platform.outbound.*` properties.

   A build test keeps this list stable through 1.x.
5. **Migration SQL unchanged byte for byte** for every schema already released, as the pinned-SQL tests check, and it runs under Flyway 12 as each schema's own run. Add a test that runs every platform schema through Flyway 12's API, as an app would.
6. **No Jackson 2 type** (`com.fasterxml.jackson.*`) in any public signature or required dependency. Jackson 3 is fine only where Boot 4.2 manages it. Add a build test.
7. **The setup command's jar runs** on Boot 4.2's library versions, as a smoke test of `java -jar` with `--help` and a dry-run plan against Testcontainers PostgreSQL.
8. **Release notes for 0.8.0/0.8.1** list the Spring versions and the defaults that changed.
