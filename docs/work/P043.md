## B. Findings

### FIX-A: SEC-1 (High), SEC-9, SEC-52

- **SEC-1:** no platform code follows a junction, symlink or other reparse point when it deletes, moves, claims or cleans up. Check this with NOFOLLOW (and the reparse-point attribute on Windows) **before every** delete, move and directory walk:
  - the folder export (`.partial`, its clean-up, the final swap);
  - the watched folder (claim, `_processing` / `_archive` / `_problem` / `_quarantine`, a stuck-claim release);
  - the erase-log location;
  - the diagnostic bundle's temporary files.

  A link found where a real folder or file is expected is refused with a specific code (`INT_FOLDER_LINK_REFUSED` / `INT_WATCH_LINK_REFUSED`, or the module's own), and nothing behind it is touched.
- **SEC-9:** the bytes handed to the app are the bytes that were scanned. Scan a private copy and hand over that copy, or hash at scan time and check before the hand-over, refusing on a mismatch.
- **SEC-52:** Windows device names are refused in names.

### FIX-I part 1 (SEC-15, SEC-40, SEC-41, SEC-59; and P042 question 3)

- **SEC-15:**
  - the release workflow publishes only when the tagged commit is on `main` and its CI run on `main` succeeded; otherwise it fails with a clear message;
  - document a **tag ruleset** for `platform-core-v*` (only the owner may create such tags; none may be moved or deleted) in the report, as an owner setting, with the exact `gh api` call. The owner applies it;
  - SEC-40 and SEC-59: workflow permissions at least privilege, and actions pinned by commit SHA, as the findings propose.
- **SEC-41:** add `.github/dependabot.yml` for Maven and GitHub Actions (weekly; grouped minor and patch). Turning on Dependabot alerts and security updates is an owner setting: give the exact steps in the report.
- **Dependency bumps that don't change the Spring line** (SEC-14 in part): httpclient5, httpcore5 and nimbus-jose-jwt to their fixed versions; check that micrometer is still optional. **Don't change the Spring Boot, Framework or Security versions in this task.** That move waits for a decision (below).
- **`ScannerTest` on the laptop** (P042 question 3): extend `Eicar.staysOnDisk` with a loopback-transfer check, so local `mvn verify` skips the test where antivirus cuts the download. CI must still run it (CI forbids skips, so CI must not hit the skip).

**Not in this task: the Spring baseline (SEC-14).** Every Spring Boot 3.x line is past open-source support (3.5's ended June 30, 2026). The fix is a move to Spring Boot 4.x (Framework 7, Security 7), which the apps must make too, so the LexaVault design chat decides it first. It is a later task.
