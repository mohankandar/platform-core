# Task P046 — move platform-core to Spring Boot 4.2; clear the Dependabot PRs; release `platform-core-v0.8.0`

Written 2026-11-23 by the Shared capabilities thread. Decided by the LexaVault design chat (board LV-18, owner-approved): **all three repos move off Spring Boot 3.x to Spring Boot 4.2** (Spring Framework 7.1; open-source support to December 31, 2027). **Platform-core moves first**, so the integration release `platform-core-v1.0.0` is built on 4.2. Read CLAUDE.md, docs/work/README.md, docs/work/P045-report.md and `docs/work/security-findings.md` (SEC-14) first. Repo C:\dev\platform-core, branch main (`0.8.0-SNAPSHOT` after P045). Everything stays generic.

**Java stays 21.**

**If any dependency isn't ready for Spring Boot 4.2, stop and report it.** Name the dependency, the problem and what would fix it. Falling back to the newest 4.1.x needs the LexaVault design chat's decision; don't do it yourself.

1. On main, the only uncommitted files may be `P046.md` and `P047.md` (they may already be committed). Commit any that aren't, as the first commit of your branch.
2. New branch `build/spring-boot-4.2` from main.

## B. Work

### B1. The move

- **Versions:** take the **newest Spring Boot 4.2.x patch** available today, and with it the Spring Framework 7.1.x and Spring Security 7.x that Boot 4.2 manages. In the root POM, import Boot's dependency management (or pin the three versions to what Boot 4.2 manages; say which). Micrometer, Nimbus and the others follow Boot 4.2's managed versions unless a fixed version is newer.
- **Every `-spring` module** builds and passes on 4.2. This covers:
  - auto-configuration;
  - configuration properties;
  - Actuator health and its package moves;
  - Security 7 configuration (lambda DSL only, removed APIs);
  - anything Boot 4 split into separate starter or autoconfigure modules;
  - JSpecify null annotations where needed.

  Fix every deprecation warning that Spring 7 or Boot 4.2 reports in our code, so nothing breaks at 4.3.
- **Plain-Java modules** keep no Spring dependency. Check that no Spring jar leaks into a plain module.
- **The behaviour doesn't change.** Every test stays green, and if a test has to change, say why. CI must have no skips (as before).
- **The public-API rule (P041) still holds.** The build test stays green.

### B2. The Dependabot PRs

Clear the open Dependabot PRs (#48–#52, and any newer ones) against the new baseline:
- **merge** those that still apply, each only on green CI with the README's stop-on-failed-check line: the GitHub Actions majors, the patch and minor group, and JUnit 6 if Boot 4.2 doesn't already manage it;
- **close** those that the move made pointless (for example Nimbus 10, if Security 7 manages it), with a comment saying why.

### B3. Prove it

- **The advisory check again:** list every third-party artifact by scope, through `mvn dependency:list` over the reactor, and check it against the GitHub advisory database through `gh api graphql`, as P042 did.
  - **Required: no open High or Critical advisory in compile or runtime scope.**
  - Anything still open is listed with its reason.
  - Mark SEC-14 `FIXED in P046 (<commit>)` in `security-findings.md`.
- **Docs:**
  - `docs/install/*.md` and `README.md` state the minimum: Spring Boot 4.2, Java 21;
  - the root POM's comment about the products' Spring lines is updated;
  - `docs/design/` gets a short "platform baseline" section (Spring Boot 4.2, Java 21, why, and when to review: before 4.2's open-source end on December 31, 2027).
