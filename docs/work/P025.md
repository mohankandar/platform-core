### B2. Proxy sign-in

- The proxy's user and password (by secret reference) are sent as Basic on CONNECT and on plain-http requests through the proxy.
- The library **never sets JVM properties**. When the proxy needs Basic and the JVM still disables it for tunnels, the first call fails with `INT_PROXY_SIGN_IN_DISABLED_BY_JVM`. That code's message names the start option `-Djdk.http.auth.tunneling.disabledSchemes=` that the install guide gives the customer.
- A proxy refusing the credentials gives `INT_PROXY_SIGN_IN_REFUSED`.
- **Test:** `MockProxy` gets an optional Basic requirement, and the tests cover right, wrong and missing credentials. They run in a forked JVM with the start option, plus one without it that proves the specific code.

### B3. Folder / network-share export with a manifest written last

A new integration kind, `FOLDER_EXPORT`, configured and versioned like API push. One attempt per call, with the same `AttemptResult` outcomes.

- **Configuration:**
  - the target folder (a local path or a UNC share path; it must be absolute);
  - the folder name template per package (fixed placeholders only, e.g. `{package.id}`, one path segment, escaped as in P023);
  - the file name template per document (default: the document's own file name, made safe);
  - the limits.
- **Writing:**
  1. Create `<folder>/<package>.partial/`.
  2. Write each document to a temporary name, flush it, check its SHA-256 against the delivery, then rename it.
  3. Write `manifest.json` **last**, also through a temporary name and a rename.
  4. Rename the folder from `.partial` to its final name.
  5. On any failure, leave or clean up only the `.partial` folder; a reader never sees a final folder without its manifest.
- **Manifest `platform-export-manifest/1`:**
  - the common envelope:
    - format;
    - package ID, correlation ID, created at;
    - product code;
    - the entity's slot ID;
    - the integration ID and its configuration version;
    - the documents: file name, source document ID, content type, size, SHA-256;
    - optional field values in the `platform-field-values/1` wire format, where sensitive fields go only if the configuration allows that key, as for API push;
  - plus `"app": { … }`, an object the app fills and platform-core never reads.

  Its JSON Schema sits next to the profile schema, and the format in words goes in `docs/design/integration-module.md` (new section).
- **Outcomes:**
  - The final folder already exists with an identical manifest → `ALREADY_RECEIVED`. With a different one → `REFUSED` with `INT_FOLDER_EXISTS_DIFFERENT`.
  - The target doesn't exist → `NOT_CONFIGURED` with `INT_FOLDER_NOT_FOUND`.
  - No permission → `INT_FOLDER_NO_PERMISSION`.
  - The disk or quota is full → `INT_FOLDER_FULL`.
  - The share can't be reached → `CANT_CONNECT` with `INT_FOLDER_UNREACHABLE`.
  - A checksum differs after writing → `UNCLEAR` with `INT_INTEGRITY_MISMATCH`.
- **Health:** the target exists and is writable. The check writes and removes a probe file, and nothing else.
- **Test action:** writes the fake PDF and a manifest into a `platform-test-<timestamp>` folder, then removes it. It is audited like API push.
- **Mock folder:** `MockFolder` in the testkit, with switches for missing, read-only, full (fails on write after N bytes), slow, and "an existing package folder".
