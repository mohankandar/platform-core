## B. Work

1. **Docs-only pull requests run a short job.**
   - A PR that changes only docs (`docs/**`, `*.md`, `README*`) runs a short `verify` job: the product-name guard plus the tests that read docs (catalogue freshness, public-API names in guides, pinned files), no full build.
   - Any other change runs the full build.
   - **The required check keeps the name `verify`** either way, so branch protection doesn't change: one job named `verify` that chooses its path from the changed files (for example with `dorny/paths-filter`, pinned by SHA, or `git diff --name-only`).
   - Docs-only is decided from the whole PR, not the last commit.
2. **Parallel Maven, only if stable.**
   - Try `mvn -T 1C` in CI and locally.
   - Keep it **only if at least 5 CI runs and 3 local runs in a row are green with the same test counts** and no new intermittent failure. Testcontainers, the TLS tests and the scanner tests are the likely trouble.
   - If it isn't stable, don't use it, and say why in the report.
3. **CI once per PR.** CI runs on `pull_request`, and on `push` **only to `main`** (so each PR runs once, and main still runs after every merge for the tag rule).
4. **Dependabot ignore list** (P046 question 1, decided): in `.github/dependabot.yml`, ignore versions of artifacts whose version Spring Boot manages (for example httpcore5, Logback) beyond Boot's managed line, so Dependabot doesn't propose overrides; Boot upgrades bring them.
5. Update the merge routine in `docs/work/README.md` if any check name or step changed (it shouldn't).
