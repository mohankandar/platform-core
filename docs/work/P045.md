## B. Findings

### FIX-D: SEC-6, SEC-31 to SEC-34

- **SEC-6:** the gate at model start checks that the live validation is **approved** by a permitted approver, in the database, not only in the service code. A direct database write of an unapproved "live" row must still be refused at the gate.
- SEC-31 to SEC-34 as proposed. This includes the PostgreSQL `pg_temp` search-path hardening on every `SECURITY DEFINER` function, across all schemas. Add a test per schema.

### FIX-E: SEC-7, SEC-16, SEC-17, SEC-18, SEC-44, SEC-45

- **SEC-7:** a person's sign-in token can never be taken for a machine caller. `PushCaller` requires the token to be a client-credentials (machine) token by a configured rule, for example no user claims, or a required machine-only claim or audience, chosen per product. The default refuses a token that carries user identity.
- The other findings as proposed. Identity's documented API stays; a new setting gets a safe default.

### FIX-G: SEC-11, SEC-19 to SEC-23, SEC-54 to SEC-56

- **SEC-11:** the bundle never copies values from mounted secret files or config trees. Go to an allow-list of configuration sources and property names, rather than scrubbing a copy of everything.
- The rest as proposed (SafeText, reference IDs, logs, health output).

### FIX-H: SEC-12, SEC-13, SEC-26, SEC-27, SEC-43, SEC-51

- **SEC-12:** the licence trust root may not be supplied by the customer.
  - The trusted keys come from a **resource inside the app's own build** (the product ships its public keys in its jar); an installation file can't add or change a key.
  - **Development keys are accepted only when the app's build turns them on.** A build-time switch, not a runtime setting, so a production build never trusts a development key, whatever the files say (also SEC-43).
  - Setup reads the same built-in key set, from the product's setup wrapper.
  - The change breaks configuration (the `trusted-keys-file` / `trusted-keys` properties go). Describe it plainly in the release notes; no app runs licensing yet.
- **SEC-13:**
  - the runtime user gets no DELETE or UPDATE on `lic_last_seen` that could move it backwards. Use a function that only moves forward, or insert-only rows;
  - add a time floor (never before the licence's issue time, nor before the release's build time);
  - new licensing schema version.
- SEC-26, SEC-27 (wording plus our-side checks), and SEC-51 as proposed.
