## B. Build (P022 report, row P023, as approved)

New modules `platform-integration` (plain Java, no Spring; package `com.documentplatform.integration`) and `platform-integration-testkit` (test scope only); add both to the build and the BOM.

- **Configuration model, store, history and audit** (B3): destinations and sources, versioned; every change kept as a new version with who and when, for the app's audit; Postgres store with SQL under `db/platform/integration` (history table `int_schema_history`, run only by the schema step; startup only verifies; DML-only runtime user) + in-memory store in the testkit. Secrets and certificates only as references (`SecretResolver`; certificates come in P026).
- **The call engine for API push** (B3): steps, templates from **fixed building blocks only (no scripting)**, response mapping. No document content or secrets in addresses, templates or logs.
- **Sign-in:** NONE (on-prem only, off by default, warned; refused when the installation is marked hosted), BASIC, API_KEY (header, never the address), BEARER_FIXED, OAUTH2_CLIENT_CREDENTIALS through a **generic token client** (generalised from notifications' Microsoft token code: any token address, scope or audience, client secret or certificate assertion, cache, specific failure codes). Microsoft stays a preset; notifications is not changed in this task.
- **Safety** (B5): cloud-metadata address guard (internal addresses allowed on-prem, configurable), outbound proxy, private certificate authority, no redirects, size limits and timeouts per integration.
- **The one-attempt result** (B4): sent / already received / refused with code / sign-in failed / can't connect / busy, plus outage. **Classification rules are data** (status + destination code → result class), so a profile can say, for example, "503 with the busy code = busy, no attempt used; 503 without it = outage; AUT-004 = sign-in fault" (owner decision 2). Retry-After passed through when sent. **The engine never retries**; the app owns the schedule.
- **Health check per destination** (configured call, its own classification) and a **Test action** with fake data that runs the full path without sending real content.
- **Mock destination server** in the testkit (JDK `HttpServer`): switches per test or by a small admin call — working, down, slow, busy (with and without Retry-After), outage (503 without busy code), refuses with a code, already received (200 replay), sign-in refused, health failing while uploads work and the reverse; its own token endpoint for OAuth2 tests; records what it received (headers, fields, checksums; never document text). Generic in this task; P024 drives it from the Vero spec.
- **Tests:** every sign-in type against the mock (and its token endpoint); every switch → the right result class; classification rules as data (including the Vero-style 503 busy vs outage rule with a made-up profile); metadata-address guard (blocked, and internal allowed on-prem); proxy and private CA; no secret or content in any log (captured logs); configuration versioning and history; Test action sends no real content; DML-only user.

Then mvn verify (all existing tests still pass, plus new), mvn install. If green: merge into main (fast-forward if possible), push main, delete the branch locally and on origin (if the remote delete is refused, note it and go on). Commit the report on main and push.
