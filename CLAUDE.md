# platform-core

Shared platform libraries for document products. Each app pulls these modules in as **libraries** (released jars on
its classpath, from GitHub Packages). platform-core is not a server, has no `main`, and is never deployed on its own.

## Modules

| Module | What it is |
|---|---|
| `platform-bom` | Bill of materials. Lists every platform module at the platform version. Products import it in `dependencyManagement`. |
| `platform-errors` | The common error-code standard (plain Java, no dependencies; package `com.documentplatform.errors`; P032): `PlatformCode` (code, kind REFUSED / FAILED / NEEDS_PERSON / INFO, user message, cause with `{placeholders}` for safe details, fix, support note, optional HTTP status) implemented by **every** platform code enum, the texts as data next to each enum in `<Enum>.codes.properties` (`*.` family and `PREFIX_*.` defaults; no code renamed); `PlatformError` (code, safe message with the reference, cause, reference, time; secret-named and secret-looking details removed by `SafeText`); `ReferenceId` (`R-` + 12 base32, time-ordered, unguessable; `current()` per request); `FailureLog` (one line `code=… ref=… cause="…"`, the last 200 kept); `HasPlatformCode` on exceptions that carry a code; `Catalogue` (Markdown and JSON). Generated catalogue `docs/errors/platform-error-codes.md` / `.json`; guide `docs/design/error-codes.md` (apps' own codes, the API error format `{"code","message","reference","details"}`, `X-Request-Id`, API versioning). |
| `platform-error-catalogue` | Build check only, never deployed, not in the BOM (the other module outside the BOM is `platform-licensing-issue`, our own issuing tool; and `platform-app-check`): every code enum implements `PlatformCode` with a message, cause and fix; codes unique across modules; no text with a gap or a `%s` slot, no user message naming internals; every exception carrying a code implements `HasPlatformCode`; every Spring start-up refusal and store failure carries its code; no code name ever disappears (`docs/errors/code-names.txt`, append only); every module on its classpath; the generated catalogue up to date (`-Dplatform.errors.write=true` regenerates it). |
| `platform-app-check` | Build check only, never deployed, not in the BOM (P051): a Spring Boot 4.2 app with Boot's starters and dependency management: each -spring module starts alone and all together on a DataSource made by Boot, every schema through Flyway 12 as its own run, one Nimbus, no Boot 3 jar, the full public API of 1.0.0 recorded (`docs/api/public-api-1.txt`, `StableApiTest`, `-Dplatform.api.write=true` adds), start-up failure reports with each module's code, no Jackson 2 in required dependencies or public signatures, names apps use stay public (`StableNamesTest`, append only), the setup command as `java -jar`. |
| `platform-monitoring` | Dependency self-checks (plain Java; package `com.documentplatform.monitoring`; P032; the modules a check uses are optional dependencies): `DependencyCheck` → `Verdict` → `CheckResult` (WORKING / HAVING_PROBLEMS / DOWN, `PlatformCode`, cause, fix, when, duration), `CheckRunner` (throw → the exception's code or `MON_CHECK_FAILED`, hang → `MON_CHECK_TIMEOUT`), built-in checks `checks.DatabaseCheck` (reach, login, each platform schema's own verify), `KeyServiceCheck`, `SecretStoreCheck`, `LoginSystemCheck` (`IDN_TEST_*`), `LicenceCheck` (never enforces), `ChannelCheck` (mail, webhook; nothing sent), `FileLocationCheck` (90 % / 95 %), `HttpServiceCheck`, `IntegrationChecks` (never required, never readiness); `DatabaseCheck` warns `MON_DB_USER_TOO_POWERFUL` (HAVING_PROBLEMS) when the app's login owns the tables or may create objects; `StartupChecks` (refuse to start, one line per DOWN required check); `DependencyStatus` (scheduler, latest results, `MonitoringEvent`s); `MonitoringCode` (`MON_*`); `DiagnosticBundle` (zip: versions, system, configuration with secrets removed, checks, last failures, schema versions, SHA-256 manifest, size limit). Stores nothing in the database. Design: `docs/design/monitoring.md`; install guide: `docs/install/monitoring.md`. |
| `platform-monitoring-testkit` | Test support for monitoring: `SwitchableCheck`, `RecordingEvents`, `MockHttpService`; holds the built-in checks' tests against the other modules' mocks. Test scope only. |
| `platform-monitoring-spring` | Spring Boot wiring for monitoring: `platform.monitoring.*`, the built-in checks from the app's modules and beans plus its own `DependencyCheck` beans, start-up refusal (a failure analyzer), the scheduler, `MonitoringListener` beans, health (`readinessState` = the app's readiness + the required checks; informational `dependencies`; replaces integration-spring's `integrations` contributor), Micrometer metrics (`platform.monitoring.check.state` / `.duration`, `platform.integration.attempts`), `RequestReferenceFilter` (always makes the reference; answered as `X-Request-Id`, MDC `ref`; the caller's own only as MDC `requestId`; before Spring Security), `DiagnosticBundles` (allow-list of sources and names, `bundle-properties`). |
| `platform-model-governance` | AI model governance (plain Java, no Spring; depends on platform-errors and Apache PDFBox for the pack's PDF; package `com.documentplatform.modelgov`; P033, P034): register `Model` (provider VENDOR / CUSTOMER, version, exact `ModelDigest`: `sha256Of(Path)`, optional `ManifestDigests` over a model server's OCI manifest API) and `ModelUse` (product, feature, entity or every entity, purpose, materiality HIGH / MEDIUM / LOW with reason, human in the loop, owners, configuration fingerprint `ConfigFingerprint.of` = `sha256:` of canonical JSON, status PROPOSED / VALIDATED / LIVE / RETIRED, last validation, next review due), versioned with history and `ModelGovAudit`; change gate `ModelGovernance` (default pass marks, customer's only stricter `MOD_THRESHOLD_LOOSER`; validation records insert only with the pass marks copied in, numbers only; `approve` by the app's approver roles, never with a forbidden role (`ModelGovSettings`; `MOD_APPROVER_ROLE` / `_CONFLICT`); failed customer model blocked for high, documented `accept` for medium; `goLive` / `rollback` per entity); `ModelGate.requireLive` at model start (`MOD_NOT_VALIDATED`, `_NOT_APPROVED`, `_NOT_LIVE`, `_DIGEST_MISMATCH`, `_CONFIG_CHANGED`, `_RETIRED`, `_REVIEW_OVERDUE` warning or refusal per use) → `LiveModel.stamp()` `ModelStamp` stored with each result; `MOD_*` codes; Postgres `jdbc.PostgresModelGovStore` (`mg_` tables, SQL `db/platform/modelgov`, history table `mg_schema_history`, run only by the schema step, startup check `ModelGovSchema.verify`, DML-only user, insert-only tables refuse UPDATE / DELETE / TRUNCATE by trigger even for the owner). P034: monitoring `ModelMeasures` (`report(use, entity, measure, value, MeasurePeriod)`, numbers only, insert-only `mg_measure` kept for the retention (default 400 days; deleted only by `purge()`), `Monitoring.MonitorThreshold` default or customer's stricter with direction and minimum sample; drift → `ModelEvent` DRIFT (`MOD_DRIFT`) to the app's `ModelEvents`, the use needs review until `recordAction`; one open drift per measure); re-validation `ModelReviews` (next review per use and entity, from that entity's live validation and the materiality or the use's own `reviewEveryDays`; due at once after a change of version, digest, where it runs, model or configuration; `due(now)` 30 / 7 days and overdue on the date, `REVIEW_DUE` once per stage, `mg_review_notice`); documentation pack `ModelPack.export(product, entity, from, to)` (JSON `platform-model-pack/1` with schema `schema/platform-model-pack-1.schema.json`, canonical, fingerprint `sha256:` of the JSON; PDF through Apache PDFBox printing the fingerprint; items 1–7 of design section 6; texts from the app's `PackTexts`); schema V4 (P037: readings leave only through `mg_purge_measures`, run as the schema owner with a 30-day floor; the runtime user needs EXECUTE on it, no DELETE on `mg_measure`. P039: each validation records where the model ran; a change of location is `MOD_LOCATION_CHANGED` at the gate for every materiality; a customer pass mark left looser by a tightened default stops counting, `looserEntityMarks` lists it; `forbidden-roles` may not be empty). Design: `docs/design/model-governance.md`; install guide: `docs/install/model-governance.md`. |

## One version

Every module inherits its version from the root `pom.xml`. Never set a `<version>` in a module POM other than
in its `<parent>` block. Inter-module dependencies use `${project.version}`. A release bumps all modules together.

## Build

```
mvn verify      # compile + all tests (the only local check; no `mvn install` into the shared ~/.m2)
```

Apps use **released versions only**, from GitHub Packages (`https://maven.pkg.github.com/mohankandar/platform-core`).
A release is a tag `platform-core-vX.Y.Z` on main; the release workflow publishes it. Tags are never moved or reused.
For an offline build of a tag into a separate local repository: `scripts/build-release.ps1` / `scripts/build-release.sh`.
Merges into main go through pull requests with green CI (`.github/workflows/ci.yml`); see `docs/work/README.md`.

Java 21, Spring Boot 4.2 (`docs/design/platform-baseline.md`), Maven 3.9+.

On the owner's Windows laptop, Norton 360 intercepts TLS; Maven trusts it via the user environment variable
`MAVEN_OPTS=-Djavax.net.ssl.trustStoreType=Windows-ROOT`. Never add machine-specific settings to the repo.

## Rules

- **Independence.** platform-core never names, depends on or assumes any product. Product-specific behaviour is
  profile **data** published by the API's owner (format `platform-integration-profile/1`), never code or files here.
  Tests use made-up profiles only. Apps plug their specifics in through interfaces (for example `EntityRoleCatalog`)
  and configuration. `NoProductNamesGuardTest` fails the build on a product's name in code, SQL, JSON, XML, YAML,
  properties, CLAUDE.md, README files or `docs/install/`.
- **Released versions only across repos,** from GitHub Packages; tags are never moved.
- **Merges go through pull requests with green CI.**
- **Never log secrets, document content or redacted values.** That includes tokens, client secrets, keys,
  passwords, raw claims, file contents, and anything that was redacted. Log ids and neutral reasons only.
- **Every code is a `PlatformCode`** (P032): a new code enum implements it, every new code gets a message, cause and
  fix in its `<Enum>.codes.properties`, and the catalogue is regenerated (`-Dplatform.errors.write=true` on
  `platform-error-catalogue`) in the same change. Never "an error occurred": say what failed, why, and what to do.
- Keep Java package names stable; renames are their own task.
- **Coordinates and packages.** Every module uses groupId `com.documentplatform.platform`. A new module puts its
  code in `com.documentplatform.<capability>` (for example `com.documentplatform.notifications`). The identity
  modules keep their existing `com.documentplatform.identity...` packages.

## Public API

What apps may use is the types each module's install guide, design doc or line above names, and what an app must
call or implement to use the module. Everything else is internal: package-private, or in a package whose name contains
`.internal`. **`internal` packages may change in any release and are not supported for apps.** Test hooks are never
public on production classes; testkits use public types or the internals of the module they test. JPMS is not used
(split testkit packages, Spring reflection); `PublicApiTest` in platform-error-catalogue checks the rule. Details:
`docs/design/public-api.md`.
